模型对比里有一个很少有人点破的默认假设：激活参数少，就意味着模型小。Qwen3.8-Flash-Next 是第一个把这条假设干净地打破的开源权重模型——125B 参数、**每 token 激活 6B**，外加 51B 的 n-gram 嵌入和 4B 的 MTP，而它在几乎每一项公开评测上都**高于**稠密的 27B。代价是：这些分数是在数据中心的满血 BF16 权重上测出来的。在我自己的机器上，同一套架构以 IQ2_XS 量化跑在 **Strata** 里——这个运行时把专家缓存常驻在显存里，而不是每次都从 PCIe 流式读取。

这篇博客记录的是我真正关心的那组对比：量化后的本地模型相对稠密 27B 能做到什么、做不到什么，以及离 DeepSeek V4.1 Flash 还剩多少。

## 1. Flash-Next 对上稠密 27B：差距在任务变长时才打开

![Flash-Next 与 Qwen3.8-27B 在十一项共有基准上的对比，右侧为逐项差值](/assets/images/fig-strata-flash-next-vs-27b.svg)

把右边那一列读成两个不同的故事。

**在单次推理类能力上，两者几乎是同一个模型。** GPQA Diamond 91.7 对 89.2，LiveCodeBench v6 91.9 对 90.3，IFBench 81.3 对 79.5，SWE-bench Pro 62.5 对 61.7。这些只是两三个点的差别——换一次 harness 重跑就可能翻过来。一个 6B 激活的模型在竞赛编程上追平稠密 27B，是这套架构最核心的结论。

**在长程智能体任务上，差距是真实的。** JobBench 55.7 对 33.4（相对 +66.8%），DeepSWE 1.1 58.7 对 42.2（+39.1%），HLE 35.9 对 30.8，NL2Repo 48.1 对 42.3。规律很一致：那些需要模型*把一份计划维持很多轮*的任务，才是多出来的参数——以及 n-gram 嵌入和稀疏注意力——真正挣到钱的地方。稠密 27B 没有地方安放这些参数；Flash-Next 把 51B 放在一张嵌入表里，它花的是内存，不是算力。

需要诚实说明的前提：这些是满血权重的分数。我机器上跑的是 IQ2_XS，Strata 自己的模型指南把它标为"更好，略低于满血"——项目并没有公布各量化档位的跑分差，所以我把本地模型当作*接近*这些数字，而不是等于。只有 IQ3_S 被声称能匹配公开测试，而它需要 54.8GB，那不是 32GB 显卡。

## 2. 离 DeepSeek V4.1 Flash 还剩多少

![Flash-Next 与 DeepSeek V4.1 Flash 在 Artificial Analysis 各子项上的相对差距](/assets/images/fig-strata-gap-to-v41flash.svg)

在同一套方法下测，总量上基本打平：Artificial Analysis 智能指数 40 对 39，Flash-Next 名义上*领先*。但这个数字掩盖了差别的形状。

**表 1.** 剩余差距落在哪里（Artificial Analysis，同一 harness，三个模型同时测量）。

| 子项 | Flash-Next | V4.1 Flash | 差距 |
|---|---|---|---|
| 智能指数 | 40 | 39 | −1（Flash-Next 领先） |
| AA-Briefcase v1.1 | 1581 | 1422 | −159（Flash-Next 领先） |
| GDPval-AA v2.1 | 1629 | 1600 | −29（Flash-Next 领先） |
| AutomationBench-AA | 56% | 69% | +13 分 |
| Terminal-Bench 4.0 | 25% | 27% | +2 分 |
| SciCode | 51% | 52% | +1 分 |
| Humanity's Last Exam | 38% | 39% | +1 分 |
| CritPt | 11% | 14% | +3 分 |
| AA-LCR v1.1（长上下文） | 80% | 84% | +4 分 |

九项里六项归 V4.1 Flash，这六项包含了其中所有智能体和长上下文的项目。DeepSeek 自己的表格在同一维度上更狠，因为它是在最大推理强度、1M token 窗口下评测的：**DeepSWE v1.1 74.2 对 58.7**——十五个点，是目前最大的剩余差距——Terminal-Bench 2.1 90.6，NL2Repo 64.0 对 48.1，CyberGym 88.1。

所以"还剩多少"不是一个数字。在知识工作和推理上，差距大约是两个点到十个点，其中一部分 Flash-Next 直接赢了。在智能体软件工程上，差距仍然是十五个点，而那恰恰是我实际用这些模型做的事。

## 3. 本地机器赢过云端的那一块

![在一块 RTX 4080 SUPER 上实测的解码速度随提示长度变化，对照官方 IQ2_XS 曲线](/assets/images/fig-strata-local-decode.svg)

Artificial Analysis 对 Flash-Next API 的基准是 52 tokens/s。我的机器跑同一套架构的 2bit 量化，日志里是 **109–212 tok/s**（112 次请求中的 64 次持续生成）——同一份权重，比云端 API 快约 3 倍。原因不是显卡更快（官方曲线是在 12GB 的 RTX 5070 上测的），原因是缓存。

来自引擎日志，只统计持续生成（256 token 以上）的请求：

- 解码在 10K token 提示以下平均 **150 tok/s**，10–40K 是 155，**40–128K 是 153**；而官方曲线从 1K 到 262K 掉了 34%；
- **99.5% 的被路由专家常驻显存**（6,494,373 次查找中 6,459,361 次命中）——走 PCIe 的路径只跑了 1,688 次；
- 提示读取在 82K token 的冷提示上峰值 3,179 tok/s，所以前缀缓存住之后，prefill 不是瓶颈；
- MTP 草稿接受率随深度上升：1K 以下 72%，40K 以上 81%，整体 79%。

最后一条最有意思。大的专家缓存不只是让模型更快；它让投机解码在深上下文里更准——而那正是小量化模型通常会退化的地方。

## 4. 这三个模型实际各自是干什么的

**表 2.** 成本与形态，按官方公布口径。

| | Flash-Next（本地，IQ2_XS） | Qwen3.8-27B | DeepSeek V4.1 Flash |
|---|---|---|---|
| 参数 / 激活 | 125B（+51B n-gram）/ 6B | 27B / 27B | 552B / 8B prefill、16B decode |
| 上下文 | 原生 262K，可扩至 1M | 256K | 1M |
| 每百万 token 混合价 | 免费（32GB 显卡 + 电费） | $0.47 | $0.1842 |
| 每智能指数任务成本 | — | $1.01 | $0.27 |
| 提示读取耗时（引擎日志） | 61 token 提示 0.55 秒；68K 冷提示 22.2 秒 | 3.86 秒 | 1.08 秒 |
| 多模态 | 是（文本、图像、视频） | 是 | 文本 + 图像 |

决策不是"哪个模型更聪明"，而是你在哪一条轴上付钱。V4.1 Flash 赢下智能体这条轴和 1M 窗口。Flash-Next 赢下知识工作这条轴和价格这条轴。稠密 27B 除了"作为普通稠密模型能塞进 32GB、不需要任何运行时技巧"之外没有赢下任何可测量的项目——但如果你想要一个行为可预期的备用模型，这仍然是真实优势。

就我自己的用法，分工很简单：**本地跑量，云端攻坚。** 一天要跑几十遍的活给本地模型，因为当单次调用的边际成本是零时，十五个点的差距不重要。需要 DeepSWE 级可靠性的那些调用——复现不了的仓库、要两百次工具调用才能定位的 bug——给云端，因为那十五个点在那里是重要的。

## 5. 我不想夸大其词的部分

有三件事这组对比无法告诉你：

1. **量化的代价没有被测量。** Strata 说 IQ3_S 匹配公开测试、IQ2_XS"略低"。没有人公布 IQ2_XS 在 DeepSWE 上的分数。我本地的模型不是表 1 里的那个模型。
2. **各家跑分表因 harness 而异。** Flash-Next 的 DeepSWE 分数是两个 harness 中取的最高值 58.7；同一个模型在 Claude Code 下和在 mini-SWE-agent 下分数不同。跨厂商的比较最多只能算近似。
3. **速度声明依赖具体机器。** 109–212 tok/s 是我这台机器的日志，靠的是 18.5k 槽的专家缓存。在 12GB 显卡上，同一个量化档位跑 79.6 tok/s。架构相同，缓存不同。

诚实的总结：Flash-Next 已经追平了与稠密 27B 的大部分差距，在综合指数上也追平了与 DeepSeek V4.1 Flash 的大部分差距。剩下的十五个点属于智能体工程，四个点属于长上下文召回——而这两项恰恰是让云端值得付费的能力。
